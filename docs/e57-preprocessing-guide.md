# E57前処理ガイド

E57は、点群・画像・カメラ情報などを1つにまとめたファイルです。このViewerの前処理では、E57をViewerが高速に読み込める画像、カメラ情報、点群ファイルへ分解します。

手順1〜7が前処理、手順8〜10がViewerで表示するときの処理です。

## 全体の流れ

```mermaid
flowchart TD
    S1["1. E57ファイルを選択<br/>prepare max pointsを指定"]
    S2["2. 前処理結果フォルダを作成<br/>&lt;E57名&gt;_prepared_dataset"]
    S3["3. E57ヘッダーを読み<br/>XMLセクションを抽出"]
    S4["4. data3Dとimages2Dを解析<br/>画像・カメラ・スキャン情報を取得"]
    S5["5. 全data3Dスキャンを<br/>最大200,000点ずつ読み込む"]
    S6["6. 座標変換・無効点除外・点数抽出<br/>スキャン姿勢をワールド座標へ適用"]
    S7["7. スキャン別点群と<br/>全スキャン統合点群を保存"]
    S8{"8. 画像に対応する<br/>スキャンGUIDがある？"}
    S9A["対応するpoints_scan_XXX.npzを選択"]
    S9B["統合したpoints.npzを選択"]
    S10["9. カメラパラメータで<br/>選択した点群を画像へ投影"]
    S11["10. 画像と点群を重畳表示"]

    S1 --> S2 --> S3 --> S4 --> S5 --> S6 --> S7 --> S8
    S8 -- "ある" --> S9A --> S10
    S8 -- "ない" --> S9B --> S10

    S3 -.-> O1["e57.xml"]
    S4 -.-> O2["images/"]
    S4 -.-> O3["cameras.json"]
    S7 -.-> O4["points_scan_XXX.npz"]
    S7 -.-> O5["points.npz"]
```

## 用語

- 点群：多数のXYZ座標で表現された3D形状です。
- スキャン：レーザースキャナーで1回取得した点群のまとまりです。
- 姿勢：位置と向きです。回転と平行移動で表現します。
- GUID：スキャンや画像を識別するためのIDです。
- カメラ内部パラメータ：焦点距離や主点など、3D点を画像上へ写すための情報です。
- ワールド座標：複数スキャンで共通して使用する3D座標です。
- 投影：3D座標を画像上の2D座標へ変換することです。

## 1. E57ファイルを選択する

Viewerの `Open E57 and prepare` から対象のE57ファイルを選びます。

同時に、GUIの `prepare max points` で保存する点数の上限を指定します。初期値は500,000点です。

値を小さくすると、前処理結果が小さくなり、Viewerの読み込みや描画も軽くなります。一方で点群が粗くなり、細かな形状が減ります。

前処理で元のE57ファイルを変更することはありません。

## 2. 前処理結果フォルダを作成する

元のE57と同じ場所に次のフォルダを作成します。

```text
<E57ファイル名>_prepared_dataset\
```

例えば `sample.e57` を選択した場合は次のようになります。

```text
sample.e57
sample_prepared_dataset\
```

前処理の途中で失敗した場合は、作成途中のファイルが残ることがあります。

## 3. E57からXMLを抽出する

E57には、点群のバイナリデータ、JPEGまたはPNG画像、スキャンやカメラのメタデータ、それぞれの保存位置を示すXMLがまとめて入っています。
<img width="707" height="398" alt="image" src="https://github.com/user-attachments/assets/55b4746e-d3a3-456a-82ce-e3ed476a19ef" />
画像出典：e57FileReader
https://jp.mathworks.com/help/lidar/ref/e57filereader.html

最初にE57ファイル先頭の48バイトのヘッダーを読みます。ヘッダーには、XMLの位置、長さ、ページサイズなどが記録されています。

E57はページ単位で保存され、各ページの末尾4バイトにはチェックサムがあります。チェックサムはデータ破損を検出するための情報であり、XML本文ではありません。スクリプトはチェックサムを飛ばしながらXMLを読み出し、次のファイルへ保存します。

```text
e57.xml
```

この処理は `tools\extract_images_from_e57_xml.py` が行います。

## 4. スキャン・画像・カメラ情報を解析する

抽出したXMLの `data3D` と `images2D` を解析します。

### `data3D`

各スキャンについて次の情報を読みます。

- スキャン番号
- GUID
- 名前
- 回転
- 平行移動

回転と平行移動は、そのスキャンの点群をワールド座標へ移すために使用します。

### `images2D`

各画像について次の情報を読みます。

- JPEGまたはPNG画像
- 画像サイズ
- 焦点距離
- 1画素の物理サイズ
- 主点
- カメラの位置と向き
- 対応するスキャンのGUID

焦点距離と画素サイズから、投影に使う `fx` と `fy` を計算します。主点は `cx` と `cy` として保存します。

現在のViewerが処理するのは、姿勢情報とpinhole camera情報を持つJPEGまたはPNG画像です。必要な情報がない画像は投影対象になりません。

画像本体はE57のBlob領域から取り出して `images` フォルダへ保存します。

```text
images\
  0000_<画像名>.jpg
  0001_<画像名>.jpg
```

解析したカメラ情報は `cameras.json` へ保存します。

## 5. 全スキャンの点群を読み込む

`tools\convert_points_with_pye57.py` が `pye57` を使い、E57内のすべての `data3D` スキャンを順番に読みます。

巨大な点群を一度にメモリへ展開すると、メモリ不足や長時間停止の原因になります。そのため、最大200,000点ずつに分けて読み込みます。

各点について、元のE57に存在するデータだけを取得します。

- XYZまたは球面座標
- 無効点フラグ
- RGB
- intensity

分割読み込みによってメモリ使用量は抑えられます。ただし、点数を減らす場合でもE57全体を順番に読むため、入力ファイルが大きいと前処理には時間がかかります。

## 6. 点群を共通のXYZ座標へ変換する

E57の点群にはCartesian座標とSpherical座標があります。

### Cartesian座標

最初から `X`、`Y`、`Z` で保存されているため、そのまま使用します。

### Spherical座標

距離、方位角、仰角で保存されているため、CartesianのXYZ座標へ変換します。

実装では、まず点数上限に基づく抽出対象を決め、そこから無効点フラグが付いている点を除外します。Spherical座標の場合は、残った有効点だけをCartesianのXYZ座標へ変換します。

点数が `prepare max points` を超える場合は、点群全体からランダムに抽出します。固定シードを使用するため、同じE57と同じ設定であれば基本的に同じ点が選ばれます。抽出対象を決めた後に無効点を除外するため、最終的な点数が設定値より少なくなる場合があります。

最後に、スキャンの回転と平行移動を適用します。

### スキャン固有の座標とワールド座標

各スキャンの点群は、基本的にそのスキャンを取得したスキャナーの位置と向きを基準にしています。これをスキャン固有の座標、またはローカル座標と呼びます。同じ物体を測定した点でも、スキャナーを設置した場所や向きが異なれば、スキャンごとのXYZ値は一致しません。

E57の各 `data3D` には、任意で `pose` が記録されています。Viewerの前処理では、`pye57` から取得したスキャンヘッダーに対して `header.has_pose()` を呼び、`pose` ノードが存在するスキャンだけ座標変換を実行します。姿勢には次の2つの要素があります。

- `header.rotation`：スキャン座標からワールド座標への回転を表すクォータニオン
- `header.translation`：ワールド座標で表したスキャン原点の位置 `[tx, ty, tz]`

ここでいうワールド座標は、このE57内のスキャンやカメラが共有する座標系です。必ずしも緯度・経度などの地理座標を意味するわけではありません。

#### 実装上の処理順

姿勢変換は、`tools/convert_points_with_pye57.py` の `read_scan_chunked()` 内で、最大200,000点のチャンクごとに実行します。1チャンクの処理順は次のとおりです。

1. 点数上限に基づいて選ばれた点のインデックスを取り出します。
2. `cartesianInvalidState` または `sphericalInvalidState` が有効な点を除外します。
3. Spherical座標の場合は、距離・方位角・仰角をCartesianのXYZへ変換します。
4. `header.has_pose()` が真なら、スキャンの回転と平行移動をXYZへ適用します。
5. 変換済みのXYZをチャンクの結果へ追加します。

したがって、`points_scan_XXX.npz` に保存されるXYZは、姿勢情報があるスキャンについてはすでにワールド座標へ変換済みです。RGBとintensityには回転や平行移動を行わず、XYZと同じ点インデックスを保ったまま保存します。

#### クォータニオンから回転行列への変換

E57の回転は、XYZの3成分ではなくクォータニオンで保持されています。`header.rotation` を次の順序の4成分とします。

```text
q = [w, x, y, z]
```

`q2r()` は、最初にクォータニオンのノルムを求めて正規化します。

```text
n = sqrt(w² + x² + y² + z²)
q_normalized = q / n
```

正規化することで、入力値に小さな丸め誤差があっても、拡大・縮小を含まない純粋な回転行列になります。ノルムが0の場合は回転を決められないため、実装では単位行列を返し、回転なしとして扱います。

正規化後の `w`、`x`、`y`、`z` から、実装は次の3×3回転行列を作ります。

```text
R = [
  [1 - 2(y² + z²),  2(xy - zw),      2(xz + yw)],
  [2(xy + zw),      1 - 2(x² + z²),  2(yz - xw)],
  [2(xz - yw),      2(yz + xw),      1 - 2(x² + y²)]
]
```

これは `pye57.to_global()` が内部で使用する `pyquaternion` の回転行列と同じ向きの変換です。

#### XYZへの回転と平行移動

スキャン固有座標の1点を列ベクトル `p_scan = [X, Y, Z]ᵀ`、回転行列を `R`、平行移動を列ベクトル `t = [tx, ty, tz]ᵀ` とすると、ワールド座標の点は次の式で求めます。

```text
p_world = R × p_scan + t
```

成分ごとに展開すると次の計算です。

```text
X_world = R00 X + R01 Y + R02 Z + tx
Y_world = R10 X + R11 Y + R12 Z + ty
Z_world = R20 X + R21 Y + R22 Z + tz
```

実装の `xyz` は、点を行方向に並べた形状 `(N, 3)` のNumPy配列です。そのため、列ベクトルの数式を配列演算に置き換えると `xyz @ R.T + t` になります。実際の `transform_points()` は次の処理を行います。

```python
rotated = np.einsum("ij,kj->ik", xyz, rotation, optimize=False)
world_xyz = rotated + np.asarray(translation, dtype=float)[None, :]
```

`i` は点番号、`j` は入力側のXYZ成分、`k` は出力側のXYZ成分です。したがって、各出力成分について `R[k, j] × xyz[i, j]` の和を取り、最後に同じ平行移動ベクトルを全点へ加えています。これは次の2つと数学的に同じです。

```text
各点を列ベクトルとして計算: p_world = R × p_scan + t
全点を行ベクトルとして計算: world_xyz = xyz × Rᵀ + t
```

`np.einsum(..., optimize=False)` を使用しているのは、パッケージ版Viewerの内部から実行したときに、`pyquaternion` が使用するBLASの行列積とQtのDLLが競合する環境を避けるためです。計算内容を変更するためではなく、`pye57.to_global()` と同じ剛体変換をBLASに依存せず実行するための実装です。

#### 変換例

スキャン座標の点 `(1, 0, 0)` をZ軸まわりに90度回転し、その後 `(10, 20, 0)` だけ平行移動する場合を考えます。

```text
p_scan = [1, 0, 0]ᵀ

R = [
  [0, -1, 0],
  [1,  0, 0],
  [0,  0, 1]
]

t = [10, 20, 0]ᵀ

R × p_scan = [0, 1, 0]ᵀ
p_world = [0, 1, 0]ᵀ + [10, 20, 0]ᵀ
        = [10, 21, 0]ᵀ
```

このように、まず回転で点群の向きを合わせ、次に平行移動で点群全体を正しい位置へ移します。回転と平行移動だけを組み合わせた剛体変換なので、点同士の距離や点群の形は変わりません。

#### 複数スキャンの統合

スキャンごとに別の回転 `R` と平行移動 `t` を適用することで、各スキャンを同じワールド座標へ配置します。

```text
スキャンAのローカル点群 ── 姿勢Aを適用 ──┐
                                           ├─→ 共通のワールド座標
スキャンBのローカル点群 ── 姿勢Bを適用 ──┘
```

`combine_scans()` が複数スキャンを結合するときには、姿勢変換をもう一度行いません。すでにワールド座標になった各スキャンのXYZ配列を `np.concatenate()` で連結し、統合後の点数が上限を超える場合だけ再度ランダム抽出して `points.npz` に保存します。これにより、異なる位置や向きから取得した複数スキャンを同じ3D空間で表示できます。

スキャンに `pose` がない場合、Viewerの前処理は回転と平行移動を適用せず、変換前のXYZをそのまま使用します。この場合、元のXYZがすでに共通座標であれば問題ありません。一方、スキャンごとに別々のローカル座標で保存されているのに姿勢情報がない場合は、統合しても点群が正しく重なりません。前処理がスキャン間の位置合わせを推定することはなく、ICPなどによる自動レジストレーションも行いません。

画像へ点群を投影するときは、ワールド座標へ変換済みの点を、今度はカメラ姿勢の逆変換によってカメラ座標へ移します。ワールド座標は、複数の点群とカメラを同じ3D空間で結び付ける共通の基準になります。

## 7. NPZファイルへ保存する

各スキャンは個別に保存します。

```text
points_scan_000.npz
points_scan_001.npz
...
```

さらに、すべてのスキャンを結合した点群も作成します。

```text
points.npz
```

統合後の点数が `prepare max points` を超える場合は、統合点群からもう一度抽出します。

例えば500,000点を指定した場合、各 `points_scan_XXX.npz` と統合した `points.npz` はそれぞれ最大500,000点になります。

NPZには次の配列を保存します。

- `xyz`：必ず保存します。
- `rgb`：元のE57に色がある場合だけ保存します。
- `intensity`：元のE57に強度がある場合だけ保存します。

現在のViewerは主に `xyz` と `rgb` を表示に使用します。`intensity` はNPZに保存されますが、表示色としてはまだ使用していません。

## 8. 画像に対応する点群を選ぶ

Viewerは `cameras.json` の `associatedData3DGuid` を確認します。

画像と特定のスキャンが関連付けられている場合は、そのスキャンの点群を使用します。

```text
画像
  ↓
points_scan_XXX.npz
```

関連付けが記録されていない場合は、すべてのスキャンを統合した点群を使用します。

```text
画像
  ↓
points.npz
```

関連付けがない画像でも表示できますが、関係のないスキャンの点が含まれる可能性があります。

## 9. 3D点を画像上へ投影する

点群はワールド座標、カメラは位置と向きを持っています。まず、ワールド座標の点をカメラから見た座標へ変換します。

```text
ワールド座標
    ↓ カメラ姿勢の逆変換
カメラ座標
```

このViewerではカメラ前方を `-Z` としています。カメラの後ろにある点や、画像範囲の外側に投影される点は表示対象から除外します。

残った点を、`fx`、`fy`、`cx`、`cy` を使って画像のピクセル座標へ変換します。

```text
3D座標 X, Y, Z
        ↓
画像座標 U, V
```

これが、3D点群を2D画像上へ写す投影処理です。

## 10. 画像と点群を重ねて表示する

最後に画像を背景として表示し、その上に投影した点を描画します。

GUIでは次の項目を変更できます。

- `point alpha`：点群の透明度
- `image alpha`：画像の透明度
- `point size`：点の大きさ
- `max overlay points`：画面へ描画する点数
- `prepare max points`：前処理で保存する点数

画像上をクリックすると、クリック位置から15ピクセル以内にある最寄りの投影点を探し、元のXYZ座標を表示します。

## 生成されるファイル

```text
<E57ファイル名>_prepared_dataset\
  cameras.json
  e57.xml
  images\
  points.npz
  points_scan_000.npz
  points_scan_001.npz
  ...
```

同じE57を再度表示するときは `Open prepared dataset` からこのフォルダを選択すると、前処理を省略できます。
